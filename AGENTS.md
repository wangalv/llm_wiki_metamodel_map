# AGENTS.md

These are the rules for any AI agent working in this vault (Claude Code, Codex, etc.). All paths are relative to the vault root, which is the folder that contains this file.

## What this vault is

- `Raw/` holds **source material** that people collect: clipped articles, transcripts, PDFs, notes.
- `Wiki/` holds **compiled knowledge** that agents write, based on those sources.
- `Schema/` defines the formats and rules, and `.agents/skills/` holds the step-by-step procedures.

## Hard rules

1. **Raw is source material, not compiled notes.**
   - Treat everything in `Raw/Sources/` and `Raw/Files/` as input to read and cite.
   - Don't restructure, summarise or "clean up" Raw files. Once a source is captured, don't edit it.
   - The one exception: after compiling a source into `Wiki/`, set its `Processed: false` to `true`. Fix other frontmatter only when a person asks you to.
2. **Write reusable knowledge only under `Wiki/`.**
   - Every kind has its own `Wiki/` subfolder — see `Schema/field-reference.md` for the current list, and `scripts/profiles/togaf-core/togaf-core-profile.md` for what each one means.
   - Never put compiled knowledge in `Raw/`, `Schema/` or the vault root.
3. **Link every compiled note to at least one Raw source.**
   - Every compiled note must list at least one Raw source in its `sources` frontmatter field.
   - Its factual claims must cite those sources inline. See `Schema/frontmatter-schema.md`.
4. **Search `Wiki/catalog.jsonl` before opening broad Raw context.**
   - For any question or ingest, check the catalog first to see what's already compiled.
   - Then open the specific Wiki notes, and only the Raw sources they cite.
   - Only scan `Raw/` broadly when the catalog and Wiki can't answer.
5. **Run `build`, `lint` and source checks before committing.** See [Checks](#checks). Don't commit while any of them fails.
6. **Don't invent citations or make unsupported claims.**
   - Only cite a source you actually opened, at a location where it actually says what you claim.
   - If the sources don't support a statement, leave it out, or mark it as an open question (see `Schema/frontmatter-schema.md` → *Open questions*).
   - Never make up URLs, authors, dates, quotes or page numbers.

## Where things go

| Content | Location | Naming |
|---|---|---|
| Captured source (Markdown) | `Raw/Sources/` | `YYYY-MM-DD-kebab-slug.md` |
| Attachment (PDF, image, …) | `Raw/Files/` | `YYYY-MM-DD-kebab-slug.ext` |
| Compiled note (any kind) | `Wiki/<Kind>/` | `Title Case.md` — see `Schema/field-reference.md` for the kind list, `togaf-core-profile.md` for which to use |
| Short activity log (append-only) | `Wiki/log.md` | written by `wiki_tool.py log` |
| Catalog of Wiki notes | `Wiki/catalog.jsonl` | generated by `build`, never hand-edit |
| Human-readable indexes | `Wiki/index.md`, `Wiki/<Folder>/<Folder> Index.md` | generated by `build`, never hand-edit |
| Manifest of Raw sources | `Schema/source-manifest.jsonl` | generated by `source-scan --update`, never hand-edit |
| Note templates | `_templates/` | `<kind>-note.md` |

Full rules: `Schema/naming-conventions.md`.

## Configuration and profile

- **What's configurable:** the note kinds (folders and tags), the allowed statuses, the required fields and the Raw naming pattern are defined in `Schema/wiki-config.json`. The tables in this file and in `Schema/` describe the defaults.
- **Domain behaviour:** extra lint rules, generated files and converters come from the active profile, in `scripts/profiles/<profile>/`. See `scripts/profiles/plugin-interface.md`.
- **Check the active setup:** run `python3 scripts/wiki_tool.py doctor`. It shows the configuration and the active profile.
- **Fields:** each kind can declare extra typed fields. The generated `Schema/field-reference.md` lists every field a note must have. After changing `wiki-config.json`, run `python3 scripts/wiki_tool.py sync-schema` to regenerate the templates and the field reference.
- **The hard rules above never change** with configuration or profile.

## Templates and frontmatter

Start every new note from its template in `_templates/`: `source-note.md` for a source, or `<kind>-note.md` matching its kind for a compiled note (e.g. `actor-note.md`, `business-capability-note.md`). Run `ls _templates/` for the current list, or see `Schema/field-reference.md`.

- **Source notes** use `Title`, `Author`, `Reference`, `ContentType`, `Created`, `Processed` and `tags: ["source"]`.
- **Compiled notes** use `tags` (exactly one tag, matching one of the kinds in `Schema/wiki-config.json`), `topics`, `status`, `created`, `updated`, `sources`, `source_count` and `aliases`, plus any kind-specific fields in `Schema/field-reference.md` (e.g. `classification_basis`, required on every TOGAF-type note).

Field rules: `Schema/frontmatter-schema.md`.

## Workflows

Use the matching skill in `.agents/skills/`:

| Task | Skill |
|---|---|
| Turn a Raw source into Wiki notes | `llm-wiki-ingest` |
| Answer a question from the Wiki | `llm-wiki-query` |
| Check the vault for rule violations | `llm-wiki-lint` |
| Merge, split, rename or refresh notes | `llm-wiki-maintain` |

`Schema/workflow-examples.md` has worked examples of each.

For Obsidian syntax (wikilinks, callouts, properties, Bases, Canvas), use the `obsidian-markdown`, `obsidian-bases` and `json-canvas` skills.

## Checks

Run these from the vault root before every commit:

```bash
python3 scripts/wiki_tool.py build          # regenerate Wiki/catalog.jsonl, Wiki/index.md and folder indexes
python3 scripts/wiki_tool.py lint           # compiled notes: frontmatter, tags, source links, source_count, links
python3 scripts/wiki_tool.py source-lint    # Raw sources: frontmatter, Processed vs coverage, manifest
python3 scripts/audit_public.py             # no secrets, local paths or plugin/cache state
```

- The git pre-commit hook (`.githooks/pre-commit`, installed by `bash scripts/install_hooks.sh`) runs the same checks. Never bypass it with `--no-verify` unless a person tells you to.
- After ingesting sources, run `python3 scripts/wiki_tool.py source-scan --update --accept-covered` so that `Schema/source-manifest.jsonl` and the `Processed` flags reflect the new coverage.
- To search, use `python3 scripts/wiki_tool.py search-catalog --query "…"`.

Every command and finding code is described in `Schema/command-reference.md`. If a command fails to run, do the check by hand using `Schema/lint-checklist.md`. Tell the person you did it by hand; don't claim the script ran.

## Every time you change the Wiki

- Update the `updated` date on each note you edit, and keep `source_count` equal to the number of `sources`.
- Record the change with `python3 scripts/wiki_tool.py log --title "<ingest|query|lint|maintain> | <subject>" --details "<sources read; notes created/updated>"`. This appends to `Wiki/log.md`.
- Prefer updating an existing note over creating a near-duplicate. Check titles and `aliases` in the catalog first.
- Never hand-edit generated files: `Wiki/catalog.jsonl`, `Wiki/index.md`, `Wiki/*/* Index.md` or `Schema/source-manifest.jsonl`.
